# 局域网协作：共享 SSH、串口与 ADB

电脑 A 可以在 ShellLF 的交互终端中使用电脑 B 的串口和 ADB shell，也可以投屏控制 B 的 Android 设备、上传安装 APK，以及浏览和传输设备文件。串口由 B 打开并应用 B 保存的波特率、数据位、校验、停止位和流控；A 通过加密链路实时收发字节，不需要在本机安装那块板卡，也不需要设备提供 SSH 服务。USB 调试授权和物理设备连接均留在 B 上；ADB 工具功能需要 A 也有 ADB 客户端，投屏另需 A 上的完整 scrcpy 工具包。

该功能在 ShellLF 内提供远程设备终端和共享 SSH 交互终端，不会安装驱动、创建 A 的系统 COM 端口或进行 USB/IP 透传。SSH 共享不是串口／ADB 共享的前提。GUI 不需要开启「外部 CLI」。

## ADB 投屏排错

设备通过 USB 连接 B 且已授权 USB 调试时，A 的远程投屏不需要设备开启 Wi-Fi 调试，也不需要开放设备的 5555 端口。A 需要完整的 scrcpy 工具包和 ADB 客户端，B 保持 USB 调试连接和设备共享权限。投屏窗口显示在 A 上。

本次修复涉及 B 的局域网流传输服务，A、B 都应使用新版程序并重建投屏连接。Windows 上启动进程后先显示「正在启动投屏」，检测到可见投屏窗口后才显示运行中；45 秒内没有窗口会停止本次进程并报告错误。错误和启动超时的 scrcpy 输出保存在程序旁 `log/` 中，便于进一步排查，日志不包含传输的视频内容。

## 开启

两端进入「设置 › 局域网协作」，使用「启用局域网协作」开关，默认关闭。未设置密码时尝试开启，会提示先填写并重复输入至少 6 个字符的配对密码；保存后再开启。UI 和网络核心均不允许无密码开启。字符数不按 UTF-8 字节数计算，已有较长密码仍可继续使用；建议使用不易猜测的较长密码。

「允许在局域网内被发现」是独立开关，也默认关闭，选择会保存到本机配置。只有协作已开启且此开关打开时，其他电脑的 ShellLF 才能通过「发现设备」找到本机；关闭时不回复发现请求，仍可输入本机的 IP 地址直接连接并配对。已有配置缺少此设置时按关闭处理。

关闭发现不会停止协作、断开已配对连接或抹掉对方保存的本机设备记录；知道 IP 的电脑仍能尝试连接，但必须通过配对授权及设备白名单检查。它是发现隐私设置，不是访问封禁；要禁止访问，应关闭协作、撤销权限或拉黑。

本机配对密码用于允许别人连接本机，和主机的 SSH 登录密码、同步密码、应用锁密码相互独立。更换配对密码会撤销此前授予的所有入站设备授权；重新启动保留密码校验值、授权和黑名单。关闭后不再监听或回复设备发现，重新启动是否开启按本机保存的选择恢复。

在 B 保存串口主机并检查参数。在「串口与 ADB 设备共享」中，把目标串口加入白名单，并开启「允许远程控制白名单中的串口和 ADB」。ADB 设备需先在 B 完成 USB 调试授权，再点击「刷新本机设备（含 ADB）」并加入白名单。未授权或离线的 ADB 设备不能借此绕过 Android 的 USB 授权。

设备共享总开关默认关闭，白名单和每台配对电脑的设备权限分别保存。它们是 B 的本地配置，不随同步功能传播。没有白名单设备时仍可配对，但 A 不能打开任何本机设备。设备控制权限与旧的 SSH 命令执行权限相互独立。

加密通信使用 TCP 45838，同时监听可用的本地地址族。设备发现使用 UDP 45837：保留广播，并在每张有可用 IPv6 地址的活动网卡加入链路本地组播 `ff12::534c:4c46`，限制为一跳；网络接口变更后会刷新成员关系。发现查询在短窗口内重试，以容忍丢包和刚启动时的成员注册延迟。同一设备的多个地址按公钥指纹去重，只显示一台设备。系统防火墙需允许 ShellLF 在私有网络入站；软件不会自动更改防火墙或映射路由器端口。

IPv4 私有地址、链路本地地址和回环地址，以及 IPv6 ULA、链路本地和回环地址可用于连接。路由器分配的全局 IPv6 地址还需与本机活动网卡的直连前缀匹配，不能以此任意连接公网地址。网卡信息短时缓存并自动刷新；旧设备的全局地址在离开原网络后仍能保留，但当前连接仍检查局域网范围。IPv4 映射地址会归一化，不能绕过 IP 黑名单或密码尝试限制。

发现通常不跨子网；禁止广播／组播、多网卡路由或 VPN 环境下可手动输入地址。示例：`192.168.1.10`、`fd12:3456::1234`、`[fd12:3456::1234]:45838`。链路本地地址必须指定**控制电脑 A 的出站网卡**，例如 `[fe80::1234%12]:45838` 或 `[fe80::1234%Ethernet]:45838`；不能照抄 B 的网卡编号。发现所得的链路本地地址会自动保留 A 的接收网卡作用域。域名解析和公网穿透仍不提供。

### Windows 防火墙检查与管理员配置

网络说明下方提供三个按钮，不要求先开启协作：

- **检查防火墙**：只读检查当前运行程序对应的两条专用规则，核对实际生效策略中的程序路径、私有网络范围、TCP／UDP 端口、来源子网、服务／接口及安全筛选条件。还会检查私有网络防火墙状态、入站及本地规则策略、可能冲突的阻止规则和当前是否连接了私有网络。首次打开设置不会自动查询或修改系统。
- **配置防火墙…**：通过系统 UAC 请求管理员授权，仅启动配置任务，不以管理员身份重启整个主程序。为当前 EXE 的绝对路径创建或修复 TCP 45838 和 UDP 45837 的入站允许规则，仅限 **Private 私有网络**、来源 **LocalSubnet 本地子网**，禁止边缘穿越。已有相同路径的专用规则会复用；名称对应其他应用时拒绝覆盖。任务完成后重新检查实际生效策略，不把“已启动提权程序”当作成功。
- **删除防火墙配置…**：同样通过系统 UAC 授权，仅删除本功能为当前 EXE 路径生成的两条本地专用规则。删除前先核对两条规则的名称、分组和程序路径；发现名称被其他应用占用时拒绝删除。原本不存在时可以重复操作；操作后复查对应规则是否确实消失，仍存在时报告未能确认删除。不会关闭 Windows 防火墙、删除系统或其他程序规则、关闭协作或清空配对授权。删除可能影响后续局域网连接；若其他允许规则仍生效，也不保证立即阻断访问。需要时可重新点击配置恢复。

不会关闭防火墙、将当前网络改为私有、开放公用／域网络、删除其他规则或绕过组织策略。未知或失败的检查不会显示已就绪。规则已就绪也不等于跨电脑连通性已验证；路由器、第三方安全软件、组织策略和对方设置仍可能阻止连接。公用或域网络需要用户自行核实信任范围并处理，不能因为点击允许规则就自动获得私有网络访问。

检测目前针对本功能管理的专用规则；如果系统原有其他允许规则，也可能能正常通信，但仍提示缺少专用规则。阻止规则检测采取保守方式，匹配到当前程序（或任意程序）和相关端口的私有网络阻止规则即提示可能冲突，不会替用户删除它们。配置失败可能留下已完成的一条专用规则，重新检查或重试会核实／修复剩余规则。若管理员任务超时，它可能仍在运行，请稍后检查。

规则名称按程序绝对路径生成，不同安装位置相互独立；将 EXE 移到新位置后需要重新配置，旧路径的规则不自动删除。系统 Windows PowerShell 和系统自带网络管理模块不可用、被策略禁止或防火墙服务异常时会报告错误。其他平台不显示 Windows 配置按钮，请使用各自的系统防火墙设置。

## 两种配对方式

设置中的「局域网协作」提供独立子模块：连接设置、配对密码、防火墙（Windows）、发现与配对、已配对的设备、本机共享、访问授权、黑名单、活动与日志。可从设置左侧展开子模块定位，不必在一块长表单中找操作。

「已配对的设备」是本机访问对方；「访问授权」是对方访问本机，两者方向不同。已配对电脑的名称、地址和操作分行展示；未配对、未共享和空黑名单均有明确的空状态。

密码配对或请求被接受后，控制端显示「配对成功」通知，注明对方电脑名和查看共享资源的位置；被控端产生新授权时也会显示通知，说明调整或撤销权限的位置。通知不抢占焦点，状态文字仍可查看。启动时读取已有配对不会重复通知，错误密码和被拒绝的请求不会显示成功。

B 允许被发现时，先在 A 点「发现设备」，选中 B 点「连接设备…」；否则输入 B 的 IP 地址再连接。此时只检查加密连接和显示 B 的设备公钥指纹，不发送配对密码，也不产生 B 的确认弹窗。

首次配对先核对 B 设置页显示的本机指纹；已配对连接固定对方公钥，身份变化会拒绝继续连接，需核实后重新配对。

- **密码配对**：A 输入 B 的配对密码，点「使用密码配对」。验证成功后自动取得 B 当时白名单内设备的控制权限，前提是 B 的设备共享总开关已开启；不要求 B 再逐台批准。错误密码不产生 B 的配对请求弹窗。以后新增的白名单项不会悄悄加入旧授权，需要 B 单独授予或 A 重新密码配对。
- **请求确认**：A 点「请求对方确认」，B 弹出申请电脑名称、真实来源 IP 和配对核对码。B 可选择「接受并允许设备控制」，授予当前白名单内设备的交互权限；或选择「接受，仅查看」，仅完成配对而不授予串口／ADB 控制权；也可以拒绝。A 自动检查结果。请求约两分钟后过期。旧 SSH 执行授权仍有独立按钮，不会隐含授予设备控制权。

授权是单向的：B 向 A 共享设备，不代表 B 同时取得 A 的设备权限。配对后，A 点击该电脑的「查看串口与 ADB」，选择设备的「打开交互终端」；设备列表只包含当前授权且仍可用的白名单项。

## 像本机串口一样使用

- 串口终端使用现有终端渲染器，支持持续输出、键盘输入、Ctrl+C、复制粘贴、十六进制收发和发送 Break，而不是一次性 SSH exec。
- A 的终端标题标明 `LAN · 对方电脑 · 设备名称 · 参数`。设备信息用于显示，实际打开的端点和参数只由 B 的保存配置决定；网络请求不能要求 B 任意打开一个路径。
- B 的串口仍然独占。B 本机程序占用时不能强行抢占；同一物理串口的多个保存配置也不能同时由不同远程终端占用。打开重复标签时会明确提示占用，不会回退到 A 的本地 COM 端口。
- 串口参数或端点变更会产生新的共享设备标识，需要重新加入白名单并授权；改名仍会使当前目录刷新。白名单标识的是串口端点及参数，不是 USB 板卡的不可伪造硬件身份：同一个 COM 口插入另一块板卡时，B 应重新核对共享对象。
- ADB 以 B 上的 `adb shell -tt` 提供交互 shell，按 B 检测到的 transport ID／设备序列号选择设备，并检查已有的启动身份。终端尺寸变化会传给 B 的 PTY。
- 断开、关闭和重连沿用终端标签行为。重连重新校验权限；权限已撤销或设备不在白名单时失败，不会转而启动 A 本机 shell 或访问 A 本机串口。
- A 不会保存这些远程设备为普通本地主机：串口标签仅使用内存中的临时主机，ADB 标签使用专属远程传输工厂，关闭后清理注册表。不会把 B 的串口配置写进 A 的主机数据库。

串口上的应用层文件协议仅按原始字节传输，不作为本轮验收项目。串口／ADB 交互标签不会提供 A 本机文件侧栏来冒充 B 的文件；ADB 文件请使用独立入口。

### ADB 投屏、APK 安装和文件管理

在 A 的远程设备列表中，ADB 设备除「打开交互终端」外，还提供：

- **投屏 / 安装 APK…**：打开该远程设备专用的 Android 工具面板，不能切换到 A 本机或 B 的其他设备。点击投屏后，scrcpy 窗口显示在 A，鼠标键盘输入通过加密通道到达 B 的 Android 设备。音频默认关闭；需要时可在启动前勾选。
- **安装 APK**：选择 A 本机的 `.apk` 文件，ADB 流式上传到目标设备并安装；不使用 A 提供的 B 本机路径，也不在 B 的电脑上保存 APK 临时文件。上限为 2 GiB，安装约 300 秒超时，界面支持取消和失败反馈。安装结果以设备返回值为准。
- **文件管理…**：打开独立双栏文件标签。左侧是 A 本机文件，右侧是 B 连接的那台 ADB 设备；复用现有上传、下载、目录浏览、创建、重命名、删除和文件编辑能力。设备上可访问的路径仍由 adbd 权限决定，不代表可访问 B 的磁盘。

三项功能沿用该电脑对该设备的独立授权和白名单；正确的密码配对自动取得当时白名单权限。B 撤权、取消共享、锁定、关闭协作或拉黑来源 IP 后，活跃通道会终止；已经执行的安装、删除和设备输入无法回滚。

A 需要本地 ADB 客户端，投屏需要完整的原生 scrcpy 2.x 或更新版本工具包；Windows 保留 `ShellLF.exe` 旁的 `scrcpy` 目录即可使用随包工具。B 需要正常运行的本机 ADB server（`127.0.0.1:5037`）和已授权的设备。无需向局域网开放 5037，也不会启用设备的无线 ADB 调试。A 上的代理仅监听随机回环端口，固定到一个已授权的设备，只允许设备 shell、sync 和指定 scrcpy socket，拒绝其他设备、B 本机文件、主机管理和任意 TCP 转发。scrcpy 转发端口也只绑定 A 的回环地址。

ADB 文件、安装、投屏和 shell 通道的操作类别、连接结束与收发字节数写入 B 的有界审计日志；不保存命令正文、文件内容或 APK 内容。日志是通道级元数据，不是逐文件路径清单或不可篡改的合规审计记录。

## 独立授权、撤销与操作日志

B 在「配对电脑的独立设备权限」中选择一台配对电脑，可以逐项授予／撤销设备，或「撤销此电脑的全部设备控制权」；在「本机正在共享的连接」中可以「立即断开」某一个连接，包括共享 SSH 终端。撤权和取消白名单会立即结束受影响的通道，不打断其他仍获授权的设备；已撤销的旧通道即使立即重新授予权限也不会恢复，需要重新连接。

撤销设备控制权、关闭设备共享、取消白名单、锁定 B、关闭协作、网络中断或 A 关闭标签，都会终止相关通道，静默无输出的设备同样会被检查。已经写入设备的字节、已经启动的设备端操作不能回滚，脱离终端的后台进程也不保证随连接关闭而退出。

**知道密码即能重新取得当前白名单权限。** 撤销是立即结束当前授权，并不是让同一个密码永久失效。需要长期禁止某台电脑时，使用 IP 黑名单或更换配对密码；共享出口 IP 和 DHCP 变化的影响见下一节。更换密码会清空已授予的入站设备权限。

`<data_dir>/lan/device-audit.json` 保留最近 500 条元数据记录，设置页展示最近 50 条：共享范围和权限变更、打开请求、拒绝、连接结束、Break、主动断开，以及连接收发字节计数。记录电脑标识、来源 IP、设备名称和设备 ID；不记录逐键内容、终端输出或密码，避免把串口登录密码写入日志。字节计数是通道接受／发送的字节，不是设备操作成功的证明。

日志使用有界原子文件保存。新的设备授权或操作不能写审计日志时拒绝继续；撤销即使遇到日志或落盘错误，也会先撤销本轮内存权限并停止通道，界面报告持久化错误。发生磁盘故障时应修复存储并确认落盘，不能把内存中的撤销等同于已经跨重启保存。

## 拒绝与 IP 黑名单

B 的申请弹窗可以勾选「拒绝并拉黑此 IP，不再显示此 IP 的请求」，再拒绝；Esc 或关闭弹窗也按拒绝处理，并遵循该勾选项。接受不会因为勾选该项而拉黑。

被拉黑后，该来源 IP 的配对尝试不进入待处理队列，不会再在 B 弹窗或显示配对请求，也不会得到设备发现回复。A 会收到“你的 IP 已被对方电脑拉黑”的明确提示。B 可在设置页的「IP 黑名单」里点击「移出黑名单」；新的设备仍需重新配对，已有且未撤销的设备授权不因解除 IP 封禁而被删除。

IP 黑名单针对 B 实际收到的连接来源，不采用请求方自行声称的地址。相同出口 IP 会共同受到限制，IP 改变后不继承原 IP 封禁；因此永久撤销一个已经配对的设备应同时使用「撤销授权」。黑名单保存在 B 的本地数据目录，跨重启保留。

## SSH 交互终端与命令

B 在「共享给配对设备的 SSH 主机」中勾选主机，并开启「允许配对设备使用 SSH 终端和执行命令」。A 通过密码配对时取得当时允许的 SSH 权限；已经配对或通过仅查看方式接受的电脑，可由 B 在其授权行逐台开启 SSH 权限。此授权独立于串口／ADB 的设备共享开关和白名单。

A 点击对方电脑的「查看共享主机」，在目标主机旁选择「打开 SSH 终端」。标签标题带有 `LAN · 对方电脑 · SSH · 主机名称`，支持持续输入输出、Ctrl+C、复制粘贴、终端尺寸变化和重连，可运行交互 shell、vim、top 等程序。同一 SSH 主机可打开多个标签，每个标签由 B 新建独立 SSH 连接，不接管或打断 B 已打开的终端。两端都需要支持此功能的新版。

连接及其跳板、代理、凭据和主机密钥检查都在 B 上执行。必须先在 B 保存可用凭据并核实主机密钥；缺少凭据或主机密钥未信任／变化时立即报错，不在 A 弹出密码或信任对话框，也不复制 B 的凭据到 A。交互终端内登录后的 sudo 等问答仍可正常使用，其输入通过加密通道到达 SSH 主机。

关闭标签会释放连接；重连重新检查配对、共享范围及 SSH 使用权限。B 取消共享、关闭 SSH 总开关、撤销该电脑的 SSH 权限／配对、锁定、关闭协作或拉黑来源 IP 后，相关终端会断开，静默无输出时也会检查。重新授权不会复活旧通道，需要重新连接。SSH 终端的打开、拒绝、结束和收发字节数记入已有的有界共享审计日志，不记录输入、输出正文或密码。

此入口不把 SSH 主机写入 A 的主机数据库，也不提供 SFTP、监控侧栏、端口转发、Telnet、B 本机 PowerShell/CMD 或远程桌面。它提供 SSH 交互终端，并非所有本地主机功能的完整镜像。不会在 A 创建虚拟 COM 端口或供第三方工具访问的 ADB 转发。

A 在「已配对的远程设备」点击「查看共享主机」，选择目标主机，输入命令并执行。B 需事先保存所需凭据并确认 SSH 主机密钥；后台命令不会绕过主机密钥验证、弹认证问答或中断 B 当前使用的终端。缺少凭据、首次未信任主机、认证失败或权限变化都会返回错误。

GUI 显示输出和退出码，可以取消。B 取消共享、关闭执行总开关、撤销设备的执行权限／授权、关闭协作或锁定应用，都会使相应执行连接中止；没有输出的命令同样会被检查。关闭连接不能撤销已经发生的远程操作，也不保证停止命令已经启动并脱离连接的后台服务。A 在 B 更改权限后可刷新共享主机列表。

「执行命令」和 CLI 仍是一次性非交互命令，没有 stdin，交互程序请使用「打开 SSH 终端」。每次命令最多 16 KiB，输出最多合计 1 MiB，连接最多约 120 秒。这些限制不用于持续的 SSH／串口／ADB 交互终端。GUI 合并显示命令输出，CLI 分别传递 stdout/stderr。

## CLI

A 先在 GUI 完成配对并开启外部 CLI；CLI 仍通过 A 的本机 IPC 请求运行中的应用，不直接读取设备身份或 B 的配置。

```powershell
shelllf-cli lan peers
shelllf-cli lan hosts 'SHA256:对方设备指纹'
shelllf-cli lan exec 'SHA256:对方设备指纹' '共享主机ID' 'uname -a' --json

# 复杂命令可由 stdin 传入，参数仅为配对设备 ID 和共享主机 ID。
'df -h; uname -a' | shelllf-cli lan exec 'SHA256:对方设备指纹' '共享主机ID' --stdin --json
```

设备 ID 取自 `lan peers`，共享主机 ID 取自 `lan hosts`；不要把 B 的主机 ID 用在 A 的普通 `exec` 命令中。发现、配对、密码和授权管理在 GUI 中完成，CLI 不提供绕过确认或修改对方授权的接口。

## 数据与协议边界

`<data_dir>/lan/identity` 保存本机 Ed25519 设备身份，`lan/access.json` 保存 Argon2id 带盐密码校验值、公钥固定信息、共享主机 ID、授权和 IP 黑名单。配对密码原文不落盘、不写数据库，不用于设备登录。Windows 对 LAN 目录设置当前所有者和 SYSTEM 的访问权限；Unix 目录权限为 0700，生成的身份文件为 0600。无法安全创建或读取身份时不会开放网络服务。协作数据目录要求支持这些权限。

通信使用 russh 提供的 SSH 加密和公钥持有证明。此监听不是通用 SSH 登录服务，只接受应用内部的配对、资源列表、设备交互、共享主机终端和命令请求，不提供任意 B 本机登录 shell、SFTP 或端口转发。共享 SSH 只能选择 B 已保存且已授权的主机 ID，不能从网络请求指定新的端点、账号或凭据。未获授权的电脑仅能查询自己的配对状态，不能查看设备列表或打开设备。

设备发现只广播设备名称、公开身份和服务端口，不广播主机数据或秘密。密码失败有每 IP 五次／五分钟的限制，并发密码验证最多两个；入站连接最多 16 个、同时执行最多四个、待确认请求最多 16 个。撤销和黑名单在后续请求及执行过程中重新检查，而非只在第一次连接时检查。

设备和 SSH 交互通道合计最多同时 16 个（仍受总入站连接限制）。串口按物理端点独占；SSH 可并行打开多个终端，ADB 可并行使用投屏、文件和安装通道。读写按最多 8 KiB 的块和有界队列处理，不无限保存输出；过慢的接收方、队列饱和或写入故障会明确结束连接，不静默丢弃输入。串口使用短超时的部分写入，以便低波特率和流控暂停时仍能检查撤销。连接保活约 30 秒，不自动重放断线前的输入。

## 验证

核心测试在临时目录中启动两个真实加密节点、使用假主机执行器，覆盖发现、密码成功／失败、配对确认／拒绝、黑名单持久化与解除、只读和按主机授权、身份变化、输出限额、A 取消与 B 撤销导致无输出任务终止、应用锁和密码更换撤销授权。UI 集成测试覆盖密码确认门槛以及弹窗拒绝并拉黑、设置页解除、重新申请后接受。测试不访问用户服务器或钥匙串。

这些是同机回环节点和无头 UI 的自动化证据；不同电脑上的广播和防火墙配置仍需按实际网络确认。

SSH 新增真实本地 SSH 服务器与两端加密节点的端到端测试，检查 B 的主机密钥未信任／变化、缺少凭据、B 端独有凭据、PTY 尺寸、二进制收发、退出码，以及撤权后实际 SSH 连接和租约释放。核心假执行器测试检查超过 1 MiB 的持续输出、同主机多标签、仅查看限制、未共享主机拒绝和静默撤权。GUI 测试检查权限状态、交互输入、撤权后重连拒绝、重新授权后重连及不写入本地主机库。这些测试不连接用户的真实 SSH 主机或系统钥匙串。

新增设备测试使用注入的串口／ADB 设备和真实加密回环节点，覆盖密码自动白名单授权、二进制双向数据、尺寸、Break、同端点占用、撤销、关闭共享、应用锁、静默取消、审计存储失败时的拒绝与撤权、日志有界落盘及不记录输入正文。GUI 集成测试使用生产终端面板和假设备检查串口／ADB 渲染、输入、撤权后重连失败及不回退本机传输。它们不替代真实 USB 串口或 Android 硬件的跨电脑验证。

## Magpie 参考

本轮阅读了 [Magpie](https://github.com/yetone/magpie) 的远端资源代理和访问控制实现：

- [`remote_magpie.go`](https://github.com/yetone/magpie/blob/main/internal/provider/remote_magpie.go)：把远端提供的资源呈现为本机可使用的资源，而不是复制远端账户秘密。
- [`remote_moved.go`](https://github.com/yetone/magpie/blob/main/internal/provider/remote_moved.go)：地址变化时先证明远端身份，再向新地址发送凭据。ShellLF 保留现有 SSH 公钥固定身份，不改成把配对密码发给任意发现响应者。
- [`access.go`](https://github.com/yetone/magpie/blob/main/internal/access/access.go) 与 [`lan.go`](https://github.com/yetone/magpie/blob/main/internal/gateway/lan.go)：独立的访问凭证、受限资源列表以及显式共享范围。

Magpie 主要共享模型 API，并不是串口驱动或 USB 透传实现。本轮借鉴的是资源代理与身份、授权分层的思路，没有复制其业务代码，也没有引入子网扫描、自动地址迁移、Tailscale 或公网穿透。

同机启动两个实际 GUI 进行隔离测试时，可分别指定独立的 `SHELLRS_DATA_DIR`，并设置 `SHELLRS_LAN_TEST_ADDRESS=127.0.0.2` 和 `127.0.0.3`，避免两个程序争用监听端口。该测试选项只接受回环地址，也可以使用 `::1`，但固定端口下不能同时启动两个绑定 `::1` 的实例。未指定隔离数据目录时拒绝开启。测试时手动连接另一实例的回环地址；它不验证真实局域网广播、组播或防火墙。未设置该变量时，正常启动会同时监听可用的地址族；系统未启用其中一种时仍可使用另一种。

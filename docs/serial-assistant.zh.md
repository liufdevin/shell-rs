# 串口助手

点击主窗口右上角的串口图标，打开「串口助手」独立标签页。入口默认显示，可在「设置 → 应用 → 串口助手」关闭。普通串口终端不再显示右侧「串口工具」，原有的 HEX 收发与退格设置可从终端标签菜单调整。

页面左侧是接收区和发送框，右侧是「多条发送」「STM32/GD32」「STC/IAP15」工具区，中间分隔线可拖动调整宽度，下方是连接参数和显示/日志控制。点右侧顶部收起按钮可隐藏整个工具区，左侧终端随之变宽，再从底部「显示工具」恢复；隐藏状态、所选页签和分隔位置会保留。选择串口和波特率后点「打开串口」；波特率可选常用值（包括 2000000），也可以选择「自定义波特率」后输入数值。可同时调整编码、数据位、校验和停止位。要更换参数，先关闭串口再修改；新接入的设备可通过刷新按钮查找。

助手直接打开本机串口，不必先新建主机。如果同一串口已由其他标签页或程序占用，需要先在原处断开。在发送框中，Enter 发送，Shift+Enter 插入换行；发送时仍按选中的 LF、CR 或 CRLF 添加行尾。

串口选择、连接参数、收发选项、过滤条件和草稿自动保存在本机，关闭标签页或重启应用后会恢复。上次选择的串口不在列表里时，接入设备后刷新即可找回。串口连接、定时发送和自动应答不会自动启动。断开串口后点「恢复默认」，可重置这些设置并清空草稿，不会删除命令组或接收区中的日志。草稿会明文保存在本机，请勿输入密码、令牌等秘密。

「编辑命令组」打开独立的「命令组」标签页：左边搜索和选择命令组，右边查看和编辑命令。也可在里面配置自动应答。「返回收发」保留编辑标签页，切换或关闭编辑页不影响串口连接。编辑中的内容与发送草稿分开，只有点「载入发送框」才替换发送草稿，且不会直接发送。

- **时间戳**：打开后为之后收到的行显示本机接收时间，已有行不补写。
- **过滤日志**：只显示匹配行，支持普通文本、正则和区分大小写。关闭过滤后恢复原日志。
- **保存日志**：将接收区保留的内容导出为 UTF-8 `.log`。有过滤时只保存匹配结果；开启时间戳时同时保存已记录的时间。关闭串口后也可以导出，重新打开串口会开始一份新日志。
- **自动滚动**：默认跟到最新输出。关闭时可停在正在看的位置，后台继续接收；再次打开跳到最新。

1. 点左侧「新建分组…」，在弹窗中输入组名并保存。可在左侧搜索或重命名分组。
2. 在右侧点「添加命令…」；选中一行后，也可用「插入命令…」将新命令放在该行之前。
3. 通过行内编辑按钮修改名称、延时和命令内容。HEX、行尾和 CRC 在命令弹窗中设置；命令表本身没有发送框。
4. 每条命令独立记住发送格式、换行、CRC 和等待时间。勾选「运行」决定是否参与整组发送；也可载入单条命令、复制、上移下移或删除，最近一次删除可以撤销。
5. 在右侧「多条发送」可直接用底部快捷输入栏输入命令按 Enter 添加（无分组时自动创建默认命令组），也可以点左侧发送区旁的「存为命令」把当前草稿加入命令组，或点右上角 `+` 打开完整表单配置行尾与 CRC。
6. 每行可直接勾选是否参与整组发送、切换 HEX 模式，点右侧以命令名称标注的按钮单条发送（即使未勾选参与整组），或从行尾 `…` 菜单编辑、载入发送框、复制、上移/下移和删除。「顺序发送」按保存顺序发送所有勾选的命令一次；「整组循环」重复发送所有勾选的命令，直到停止。
7. 每条本地串口写入完成后再等待指定时间，然后发送下一条；循环时末条的等待时间同样生效。右侧显示当前命令和循环轮次，「停止」始终位于列表上方。错误或超时停止，等待写入不等于设备已执行完成，响应匹配请使用自动应答。

「停止」不会撤回已经发出的数据。关闭助手、切换标签（包括进入命令组编辑页）、重连或断开都会停止命令组和整组循环；切换标签不会关闭串口。运行期间不能切换组或修改命令。命令组与自动应答、定时发送互斥，避免同时发数据。单条草稿的定时发送仍有 60 次上限，整组循环需手动停止。

命令组按所选串口保存在本机数据库。如果该串口恰好对应一组旧版按主机保存的助手配置，会继续使用该配置。每个串口最多 32 个组，每组 128 条命令。名称最多 128 字节，单条内容最多 4 KiB，命令内容合计最多 256 KiB。命令不参与云同步，内容为明文，请勿保存密码、令牌等秘密。

## 串口 ISP

右侧可切换「多条发送」「STM32/GD32 ISP」「STC/IAP15 ISP」。先打开目标串口，再进行检测或烧录。原命令组继续保留，ISP 的固件路径、参数与命令组分别保存；打开应用不会自动烧录。

### STM32/GD32

1. 按目标芯片手册设置 BOOT 引脚并复位，进入 USART Bootloader，连接对应的 USART TX/RX 和 GND。
2. 可先点「检测芯片」读取 PID 和 Bootloader 版本，此操作不擦除或写入固件。
3. 选择 `.bin`、`.hex`、`.ihx` 或 `.ihex` 固件。BIN 起始地址默认 `0x08000000`，按十六进制填写；Intel HEX 使用文件中记录的绝对地址，检查校验和、重叠、地址溢出和结束记录。
4. 设置烧录波特率，默认 115200。ISP 临时使用 8E1、无流控，结束后恢复原串口参数。
5. 点「擦除并烧录…」并确认。助手会检查能力并读取实际 Flash 容量，然后整片擦除、分块写入。默认回读校验后启动程序，也可关闭回读校验或启动。

当前支持具有标准 USART Bootloader、可识别 PID 和已知容量寄存器的兼容芯片，包括常见 F1、部分 F0/F4 及兼容 GD32。未知 PID、容量无法可靠读取、固件越界或缺少必需命令时，会在擦除前停止。不会解除读写保护，不会修改选项字节。整片擦除包含 Flash 中的用户数据，并非只覆盖固件涉及的区域。读保护、其他 GD32/STM32 系列以及非标准 Bootloader 需使用对应厂商工具。

### STC/IAP15

使用所选 Python 环境中的 `stcgal` 后端，支持 `stc15`、`stc15a` 协议及其自动识别。需要先在该环境安装依赖，例如 `python -m pip install stcgal==1.10`，再在界面填写或选择这个环境的 `python.exe`（其他平台选择 Python 可执行文件）。

1. 选择 STC15/IAP15 的 BIN 或 Intel HEX 固件；地址必须从 0 开始，镜像上限 64 KiB。后端识别实际芯片代码区容量后，会在擦除前再次检查，拒绝未知型号、超出容量或跨入 EEPROM 的镜像，避免后端自动截断固件。
2. 协议默认自动识别，也可明确选择 `stc15` 或 `stc15a`。本入口不烧录其他 STC 协议族。
3. 点「检测芯片」或「擦除并烧录」，在后端提示等待 MCU 时给目标板重新上电。握手波特率固定为 2400，写入使用界面设置的波特率。
4. STC 后端接管串口期间，原助手先释放串口句柄。操作完成、失败或取消后重新打开原连接并恢复参数。后端的芯片识别信息、写入进度和诊断输出显示在右侧。

STC 校验采用后端的协议写入确认，不提供 STM32 式独立回读校验。芯片选项和时钟校准由 stcgal 的对应协议处理，本界面不传入额外选项覆盖。检测最长等待 60 秒，烧录最长 10 分钟；超时会终止此次后端进程并恢复串口。

### 停止与互斥

ISP 期间，停止命令组、定时发送和自动应答，阻止终端键盘、发送框及其他发送入口插入数据。运行期间不能改 ISP 参数或切换右侧页签；顶部「停止」始终可见，进度与日志区域分别显示状态。切换到其他应用标签页、关闭助手或断开连接也会取消。停止后等待当前操作退出、恢复串口，再重新操作；自动应答和命令循环不会自动重新启动。已经擦除或写入的数据不能撤回，中断后可能需要复位并重新烧录。

所有协议测试使用模拟响应或注入传输；接入新的芯片型号后，仍需在实际开发板上核对 BOOT 接线、容量识别和烧录结果。
